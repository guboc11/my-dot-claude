$ARGUMENTS 패널이 생성한 모든 태스크를 의도에 어긋나지 않게
꼼꼼히 완수할 수 있도록 끝까지 매니징해 주십시오.

## 핵심 — 워커가 결정을 물어올 때

1. 전체 맥락과 프로젝트 규칙, 사용자의 의도와 대화 패턴을 분석해서
   결정할 수 있으면 매니저가 결정합니다. 사용자에게 묻지 않습니다.
2. 정말로 결정하지 못하겠으면 「사용자라면 이렇게 고르실 것」을 생각해
   **임시로** 판단하고 진행시킵니다. 이 건은 따로 메모해 둡니다.
3. 태스크를 전부 끝낸 뒤 최종 보고에서 모아 승인을 구합니다.
   「저희끼리 프로젝트 맥락과 사용자의 결정 이력을 최대한 분석했는데도
   결정하지 못한 부분입니다. 이러이러한 후보 가운데 사용자께서 이렇게
   판단하실 것 같아 이렇게 진행했습니다. 괜찮을까요?」

## 운영

- 착수 전: `cmux tree`로 surface를 확인하되, **거기 보인다고 이 팀 패널인 것은 아닙니다.**
  쉬고 있는 패널도 마찬가지입니다. 쓸 수 있는 것은 관리자가 이번 팀 몫으로 배정한 패널뿐이고,
  다른 팀 패널은 허락 없이 가져다 쓰지 않습니다. 더 필요하면 근거와 함께 관리자에게 요청합니다.
- 담당 파악: 태스크의 `owner`는 **만든 사람**이지 담당자가 아닙니다. 매니저가 만들어 워커에게
  준 태스크는 `owner`로 찾으면 빠집니다. 그룹의 `members`와 태스크의 `assignee`로 확인합니다.
  `task_list(all:true)`가 각 줄에 담당자를 보여 줍니다.
- 지시: `cmux send` 뒤에 별도 호출로 `send-key Enter`를 보냅니다. 대본은 cmux 글에 싣지 말고
  태스크의 `spec`과 `instruction`에 담습니다. cmux 글은 어느 그룹에서 `task_next`로 일을 받으라는
  짧은 신호입니다. 보고에는 실제 출력을 붙이게 합니다.
- 흐름을 끊지 않습니다. **검증이 도는 동안 워커를 세우지 않습니다.** 배치에는 끝 상태가 없어
  앞 배치의 검증 중에도 워커는 다음 일을 받습니다. 순서가 필요하면 그 태스크의 `depends_on`으로 잇습니다.
  검증에서 나온 수정은 리뷰어의 거절이 만든 `feedback` 태스크로 따로 갑니다.
- 보고: **워커가 결과를 적는 순간 도구가 매니저 패널로 한 줄을 보냅니다.** 이것이 기본 경로입니다.
  줄 끝의 그룹과 번호로 `task_get`을 불러 전문을 읽고, 그때 그 보고가 읽음으로 바뀝니다.
  못 보낸 것은 `message_list`의 `failed`로 확인합니다. 화면을 지켜봐야 결과가 오는 것이 아닙니다.
- 감시: 보고가 **올 수 없는** 자리를 잡는 예비 장치입니다. 워커가 권한 물음에 막히거나 용량
  오류를 만나거나 입력이 씹히거나 프로세스가 끝나면 결과를 적지 못하고, 그런 자리는 기록에도
  남지 않습니다. 그 경우에만 필요하므로 아래 장치를 늘 걸어 둘 이유는 없습니다.
  걸 때는 Monitor 감지와 ScheduleWakeup 270초 안전망을 한 쌍으로 겁니다.
  오판은 양쪽 다 복구가 쌉니다. 헛깨면 확인 턴 하나를 쓰고, 놓치면 안전망이 받습니다.
  그래서 감지는 단순하게 두고 판단은 깨어난 매니저가 화면을 직접 보고 합니다.
  1. Monitor — 5초 간격으로 `cmux read-screen`을 읽어 멈춤을 감지하면
     한 줄 출력하고 스스로 종료하는 스크립트를 겁니다.

     ```bash
     miss=0
     while true; do
       s=$(cmux read-screen --surface surface:N 2>&1) || { echo "cmux 실패"; exit 1; }
       if echo "$s" | grep -qE "esc to interrupt|… \([0-9]"; then miss=0
       else miss=$((miss+1)); [ $miss -ge 3 ] && { echo "워커 멈춤"; exit 0; }
       fi
       sleep 5
     done
     ```

     - 작업 중 신호는 상태줄의 `esc to interrupt` 또는 라이브 스피너 `… (18s`입니다.
       턴이 끝나면 같은 자리가 `✳ Cooked for 38s`처럼 과거형 for로 바뀝니다.
       동사는 매번 다르므로(Cooked · Brewed · Worked 등) 동사로 맞추지 않습니다.
     - 3회 연속(약 15초) 신호가 없을 때만 멈춤으로 판정합니다. 상태줄이 캡처 밖이거나
       턴 사이 공백인 순간의 헛깸을 줄이려는 것이고, 그 이상 정밀하게 만들 필요는 없습니다.
     - cmux 실패도 한 줄 내고 종료합니다. 조용히 죽는 상태를 만들지 않습니다.
  2. 같은 턴에 ScheduleWakeup 270초를 안전망으로 겁니다.
  3. Monitor가 먼저 잡으면 검증하고 다음 지시를 보낸 뒤, 다음 사이클의 Monitor와
     ScheduleWakeup 270초를 다시 겁니다. ScheduleWakeup은 다시 부르면 이전 예약을
     대체하므로 안전망을 되돌리려고 따로 해제할 일이 없습니다.
  4. 안전망이 먼저 돌면 손으로 확인합니다. 워커가 아직 일하는 중이면 Monitor는 그대로 두고
     ScheduleWakeup만 다시 겁니다. Monitor가 죽어 있으면 TaskStop으로 정리한 뒤 새로 겁니다.
     Monitor를 쌓지 않습니다.
  5. 둘 다 돌아도 해롭지 않습니다. 각자 깨어나 상태를 보고 판단할 뿐입니다.

  매 턴 끝에 다음 깨어날 시각을 사용자에게 밝힙니다.
- 판정: 워커의 말을 믿지 말고 직접 다시 실행해 검증합니다. 판정한 뒤 다음 지시는 바로 보냅니다.
  워커를 세워 두지 않습니다.
- 금지: 커밋과 푸시, 임의 `/compact`, 다른 패널 산출물에 손대는 것입니다.
