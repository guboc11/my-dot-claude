# 스펙·계획서 작성 스킬

관리자와 나누었던 대화 내용 또는 계획 초안(brief-plan 스킬로 발화한 것)을 기반으로, 작업을 위한 스펙과 계획서를 작성하십시오. 산출물은 SPEC.md와 PLAN.md 두 파일입니다. 작성 위치는 상황마다 조금씩 다르므로, 그 프로젝트에서 계획서를 넣기에 가장 알맞은 곳을 찾아 거기에 생성하십시오.

계획서를 작성하기 전에 반드시 읽고 숙지해야 하는 것이 있습니다. 프로젝트 전체 구조, 프로젝트 규칙, 문서 작성 컨벤션 3가지입니다. 어떤 작업이든 이 세 가지는 빠짐없이 읽고, 숙지한 내용을 스펙과 계획서를 작성할 때 반영해서 작성하세요. 문서 작성 컨벤션에는 스펙과 계획서 작성 메뉴얼도 포함되어 의미하니 꼭 숙지하세요.

작업이 프로젝트 코드 또는 데이터와 관련된 것이면 위 세 가지에 더해 코드 전체 구조와 코드 작성 컨벤션까지 읽고 숙지해서 스펙과 계획서에 반영하십시오. 리서치나 도구 생성처럼 프로젝트 코드와 무관한 작업은 코드 관련 내용을 보지 않아도 되므로 필수 세 가지만 숙지하면 됩니다.

어떤 문서가 어디에 있는지 확인하고 필요한 문서를 읽을 때는 docs-explorer mcp를 사용해 읽으세요. 계획서 작성 전에 한해 특정 섹션만 뽑아 읽지 말고 관련된 파일이면 파일 전체를 읽으세요.

계획서를 작성한다는 것은 뒤이어 태스크를 생성한다는 것을 염두에 두고 작성한다는 뜻입니다. 태스크마다 그 태스크를 수행하는 에이전트가 읽어야 할 문서, 파일, 링크가 있으면 그 태스크의 참고 자료로 계획서에 메모해 두십시오.
